TrackMan 连接问题故障排查指南

您遇到了以下问题：

TrackMan 已连接并在 TPS 中显示数据，但 SwingCatalyst 未被触发，且 SwingCatalyst 中没有任何数据。

  • 重启 TrackMan 设备本身。

  • 检查您是否在 TPS 中接收到数据，如果没有，请重新检查校准设置。

  • 确认 TPS 设置中已启用"Enable SDK Output"/“Legacy SDK”。

在 SwingCatalyst 9.7.8 和 9.7.9 中，此问题已得到进一步改善。如果您按照上述步骤操作后仍未解决问题，请确保您运行的是 9.7.9 或更高版本，这有助于减少延迟。

SwingCatalyst Launch Monitor 延迟补偿

如果您已接收到数据，但 SwingCatalyst 未触发录制，请尝试将"Trigger delay"值更改为 1400。

TrackMan 3e

您也可以通过设备的网页界面检查是否启用了"Legacy SDK"。您可以从 TPS 设置进入网页界面，强制操作员模式并在准备姿势下进行检查。

如果 TPS 和设备上均已设置 SDK 输出，但仍未获取数据，请尝试使用名为 Hercules 的工具连接到设备或 SDK。

监控设备 / TPS 软件的输出：

  • 确保 TPS 正在运行并从设备接收数据。

  • 下载并运行 Hercules。

  • 切换到 TCP Client 选项卡。

  • 输入以下 IP 和端口，然后点击连接。

WiFi 和 USB IP 地址

TrackMan 4

  • 以太网：不支持。

  • USB 地址 169.254.0.1 端口：52950

  • WiFi 地址 172.30.20.1 端口：52950

  • 未知地址来源：169.254.88.214

TrackMan 3e：

  • USB 地址 169.254.0.1 端口：52950

  • WiFi 地址 172.30.20.1 端口：52950

TrackMan 2：

  • 直接连接到 TPS SDK 服务器，地址 127.0.0.1 端口：52950

如果在 Hercules 中连接成功，点击连接按钮后您应看到以下输出。

如果没有看到上述输出，请尝试重启 TrackMan 设备本身，TrackMan Legacy SDK 未输出数据。

如果连接成功，您应会接收到数据以及每次击球被追踪后的击球数据。

这与 SwingCatalyst 接收到的数据相同，是确认 TPS 和 TrackMan 确实在发送数据的好方法。

如果无法连接，请检查防火墙设置。如果通过 WiFi 连接，TrackMan 可能被识别为公共网络，这可能会与某些防火墙产生冲突；请尝试关闭公共网络的防火墙后再次检查，现在是否能获取数据？如果可以，请确保 TPS 以及 Swing / Motion Catalyst 已在 Windows 防火墙中被允许。

检查 SwingCatalyst 的日志文件：

C:\ProgramData\Swing Catalyst\logs\log.txt 如果您在日志中看到以下消息，说明 TrackMan OEM 服务正在运行，需要将其禁用。

LaunchMonitorNetworkClientBase.OnTryConnectCompleted(): Successfully connected to [Trackman] on [127.0.0.1:8000].
